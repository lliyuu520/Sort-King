# 《分类之王》开发计划（微信小游戏 · Cocos 3.x）

> 日期：2026-09-11（修订：引擎从自研 Canvas 换成 Cocos Creator 3.8.x）
> 一句话：把盲盒翻开的立体玩具拖进同类盒子，装满 5 个就消除。
> 交付：微信小游戏（`compileType: game`），Cocos 构建出包，不是浏览器 HTML 原型。
> 现状：浏览器 Canvas 原型已能玩，**只当规则对照，不再当上线路径**。
> 基础设施：素材与域名复用怒雷那套阿里云，不新开桶。怒雷是试点，用来摸清小游戏规则和备案；本项目不沿用它的「禁止引擎」。

## 0. 产品锁死（先拍板，再写代码）

这些决定后面每一期都遵守。想改，先改这一节。

| 项 | 决定 |
|----|------|
| 名称 | 中文 **分类之王**，英文 **Sort-King**。工程目录 `Sort-King`，Cocos 包名 `sort-king` |
| 玩家 | 4–8 岁为主，家长用微信打开陪玩 |
| 平台 | **微信小游戏**。竖屏 |
| 引擎 | **Cocos Creator 3.8.x**。官方导出微信小游戏。不引入 Unity / Laya / Three.js |
| 画面 | **2.5D 桌上玩具**：物品和盒子是 3D 模型，摄像机锁死，不能旋转缩放 |
| 为什么换引擎 | 要体积、高光、按下去像能摸。Canvas 贴纸做不到这一档；怒雷禁引擎是试点的最短路径，不套到本项目 |
| 核心动作 | 只有一个：手牌 → 同类盒 |
| 失败 | **没有失败**。关卡只赢、可重玩；无限模式只记最高分 |
| 盒子 | 开局匿名。第一次放对后显示分类名 |
| 手牌 | 可见上限 4，取走自动补翻 |
| 商业化 | 本周期免费、无广告、无虚拟支付。儿童向，不接激励视频 |
| 进度 | 只存本地 `wx.setStorage`。本周期不做登录、世界榜、开放数据域 |
| 素材 | **3D 模型走已有 CDN，不打进主包**。加载失败用色块/emoji 占位，不挡开局 |
| 后端 | 本周期不部署新服务。不要复用怒雷 `/nulei/api` |
| 物理 | **关掉 3D 物理（ammo.js / bullet）**。拖拽 = 屏幕射线打到桌面平面；入盒是逻辑判定，不是刚体碰撞 |
| 不做 | TCG、棋盘三消、道具商城、账号、云开发、新开 OSS 桶、自由旋转摄像机 |

砍掉已有但未接线的半成品（迁到 Cocos 时不要带过去）：

- `BOARD_W` / `BOARD_H`、关卡 `initial`：当前发牌不用
- `unlockBinSlot` / `props.unlockSlot`：4 盒默认全开
- `tutorialDone`：只写标记，没有引导 UI

**原则：** 浏览器版冻结为可玩原型。主线以 Cocos 构建进微信开发者工具为准。玩法规则继续复用现有 `Game` 状态机（改写成 TS 纯逻辑）。微信规则、备案、CDN、4MB 主包沿用怒雷试点结论。

## 1. 怒雷试点留下什么、本项目改什么

对照仓库：`D:\project\personal`（`lszj/` 客户端 + `nulei-server/` 榜服务）。密钥仍只放 `.env` / `~/.acme.sh/cdn_creds.env`，**不进本仓库**。

### 1.1 照收（平台规则，与引擎无关）

| 项 | 决定 |
|----|------|
| 形态 | 微信小游戏，不是小程序里嵌 Canvas |
| 方向 | `portrait` |
| 主包 | ≤ 4MB（代码 + 首场景）。Cocos 运行时很肥，**主包关门改为 < 4MB**，不再追求 < 1MB |
| 总包 | 主包 + 分包 ≤ 20MB（有虚拟支付才到 30MB；本游戏无支付，按 20MB） |
| 远程 | 脚本不能走远程；模型/贴图可以 |
| 合法域名 | 提审前 `downloadFile` 加 `https://oss.lliyuu520.cn` |
| AppID | **自己的号**。怒雷已占用一个，不能共用 |
| 备案 | 新游戏单独备案。怒雷只证明流程走得通，证不能共用 |
| 审核 | 儿童益智：隐私协议首屏同意、无诱导分享、无未声明广告、类目「休闲 / 益智」 |
| 存档 / 振动 / 前后台 | `wx.setStorage` / `wx.vibrateShort` / `wx.onShow` `wx.onHide` |
| 安全区 | 胶囊避让 + `safeArea` |

### 1.2 OSS + CDN（本周期要用，前缀改成模型）

| 项 | 怒雷现状 | 《分类之王》用法 |
|----|----------|----------------|
| 桶 | `lliyuu520`（成都 `oss-cn-chengdu`） | 同一桶 |
| 对外域名 | `https://oss.lliyuu520.cn/` | 同一 CDN 域名 |
| 怒雷对象 | `sprites/*.png`、`audio/bgm.mp3` | **不要占用这两个前缀** |
| 本游戏对象 | — | `sortking/models/<key>.glb`（key 与 `ITEMS` 的 `cola` 等一致）；UI 图走 `sortking/ui/` |
| 加载 | 怒雷：`wx.createImage()` | Cocos：构建填远程服务器地址 `https://oss.lliyuu520.cn/sortking/`，用 Asset Bundle / 远程包。失败占位，不卡开局 |
| 更新 | 覆盖同名 + `RefreshObjectCaches` | 同样。Cocos 可开 MD5 Cache；**不要**再给 URL 加手写 `?v=` |
| 失败 | 程序化绘制回退 | 色块 / emoji 占位，不挡开局 |
| 凭据 | 环境变量或项目 `.env` | 复用同一套，本仓库只放脚本不放值 |

上传后必须：

1. 用 CDN 域名 HEAD/GET 核对体积
2. 改过的文件调一次刷新
3. 微信公众平台 **downloadFile 合法域名** 加 `https://oss.lliyuu520.cn`

开发者工具调试阶段可勾选「不校验合法域名」；提审前必须配上。

### 1.3 服务器（本周期不用，只记着）

与上一版相同：以后若做世界榜，新开 `location /sortking/`，不要挂到 `/nulei/`。本周期不请求、不配 request 合法域名。

## 2. 引擎与画面（本项目新锁死）

### 2.1 为什么是 Cocos 3.8，不是别的

| 候选 | 结论 |
|------|------|
| Cocos Creator 3.8.x | **用这个。** 官方微信小游戏构建、2D UI 叠 3D 物、远程包和分包是现成的 |
| Unity | 主包和导出链对这个体量过重，不用 |
| Laya | 生态和微信文档不如 Cocos，不用 |
| Three.js 自适配 | 等于再写一套平台层，不用 |
| 自研 Canvas 2D | 怒雷试点路线。本项目要立体玩具，放弃作为上线路径 |

### 2.2 画面怎么做才像能摸

- 摄像机：**锁死**。略俯视书桌（约 35°–45°），正交或很弱的透视。4–8 岁，禁止旋转、禁止捏合缩放
- 物品：每个 `ITEMS` key 一个 GLB，黏土/塑料玩具风，有厚度、有高光、有接触阴影（blob shadow 即可，不要全场景实时阴影）
- 盒子：3D 盒，匿名时盖着；第一次放对揭盖并亮分类名
- 手牌：桌上 4 个可见玩具（或卡槽里的立体物），拖起来略抬离桌面，影子跟着走
- UI：分数、按钮、隐私弹层用 **Cocos 2D UI** 叠在 3D 上，不要用 HTML
- 按压：点中时 squash + 回弹。这是「想去碰」的主要来源，模型再好没有这一下也是展品

现有 41 张 PNG **不是**运行时主资产，只当建模对照。同一张扁贴纸贴到 3D 面上，换引擎等于白换。

### 2.3 包体策略（Cocos 在微信上的事实）

Hello World 不裁剪、不分包，构建后主包经常直接超过 4MB。本项目从第一天就按这个切：

1. **功能裁剪**：关 3D 物理、WebGL 2.0、视频、WebView、地形、光照探针、Tiled、Spine、DragonBones。开 3D 渲染、基础动画、2D UI
2. **启动场景极瘦**：首包只留加载页 / 隐私同意 + 进首页所需最少代码。游戏场景和模型不进主包
3. **玩法场景 = 小游戏分包或远程 Bundle**。模型优先远程（CDN），脚本只能在主包或分包里
4. 可开微信 **分离引擎** 插件换主包空间（首次会多一次引擎下载，可接受）
5. 构建填远程地址：`https://oss.lliyuu520.cn/sortking/`，把 `remote/` 上传到对应前缀

验收口径：主包 **< 4MB**（能上传）；首屏弱网能进首页，模型随后亮。

## 3. 工程结构

浏览器原型保留在仓库里对照，**不作为构建入口**。Cocos 工程放 `client/`，避免和现有 `js/` `index.html` 搅在一起。

```
Sort-King/
├── client/                 # Cocos Creator 3.8 工程（上线入口）
│   ├── assets/
│   │   ├── scripts/        # TS：Game 状态机 + 输入 + UI
│   │   ├── scenes/         # boot（主包）/ home / play
│   │   └── ...
│   ├── settings/
│   └── ...
├── prototype/              # 现有 Canvas 原型迁入（index.html / js / css）
├── assets/items/           # PNG 对照图，不进微信包
├── assets/models/          # GLB 源文件，上传 CDN，不进微信包
├── scripts/                # OSS 上传 / CDN 刷新 / 体检
└── docs/
```

`Game` 不直接调 `wx` 或 Cocos 节点。三层：

- `Game`：纯 TS，牌库 / 手牌 / 盒子 / 拖拽规则（从现有 `js/game.js` 搬）
- `PlayView`：3D 场景、射线拖拽、squash、入盒动画
- `WxShell`：胶囊、隐私、存档、振动、前后台（Cocos 的 `sys` / 微信适配层）

## 5. 分区与状态

一张牌同一时刻只在一个区（规则不变）：

```
deck → slots[4] → drag
                 ↘ bins[4]  → 满 5 个离场
放错 / 没放到盒子：drag → 原 slot
```

结算：校验同类 → 入盒计分 → 满则清空 → 补手牌到 4 → 检测关卡目标。

3D 只改变「槽位和盒子在世界里长什么样」，不改变这张表。

## 6. 分期

每期结束必须能在**微信开发者工具模拟器**里玩。真机预览是 P0 关门条件。

### P0 — Cocos 进微信 + 占位物能拖（约 3–4 天）

1. **脚手架**
   - 安装 Cocos Creator 3.8.x，在 `client/` 建工程，竖屏
   - 功能裁剪按 §2.3
   - 构建「微信小游戏」，模拟器里看到启动场景
   - AppID：正式号或测试号
2. **瘦主包**
   - boot 场景进主包；玩法场景进分包或远程
   - 确认构建产物主包 < 4MB，否则先裁再写玩法
3. **逻辑迁入**
   - `js/game.js` + `levels.js` + `i18n.js` 改写成 `client/assets/scripts` 纯 TS
   - `node` 侧继续跑规则测试（从 `js/test-logic.js` 迁）
4. **3D 对局（占位）**
   - 锁死摄像机的书桌
   - 4 个盒、4 个手牌用几何体/临时模型
   - 触摸：按下拾取、移动沿桌面平面、松手逻辑入盒或弹回
   - 点中 squash
5. **微信壳**
   - 避开胶囊；对局返回确认；首屏隐私同意；前后台暂停
6. **冻结半成品**：UI 不露道具解锁

验收：

- 模拟器走完「首页 → 无限一局 → 第 1 关过关」（占位物即可）
- 真机能拖，松手进盒
- 断网或远程失败仍能用占位物玩完一局
- 主包 **< 4MB**
- `.env` 不在上传列表里

### P0.5 — 模型管线（和 P0 可重叠，但是换引擎的真正成本）

没有这一步，Cocos 里仍是扁的。

- 风格：塑料/黏土玩具，统一比例（手掌能握住的那种）
- 先做 3 个英雄资产：苹果、香蕉、可乐罐（纠正现有「吸管杯」不像可乐的问题）
- 再铺 41 个 key 的 GLB，命名与 `ITEMS` 一致
- `scripts/oss_upload_models.py` PUT 到 `sortking/models/<key>.glb`
- `scripts/cdn_purge_models.py` 刷新
- 体检：本地 GLB ↔ OSS key ↔ `ITEMS` 三方一致
- 面数/贴图预算：单件要能在低端安卓上 4 个手牌 + 4 盒同时亮，不卡拖拽

验收：第 1 关 4 个可见物品是模型不是方块；CDN URL 无 query；失败回退占位。

### P1 — 先教后考（约 2–3 天）

与上一版相同（20 关教学环、盒上类名、hint、连击关不塞新类）。表现改成 3D 揭盖，规则不改。

验收：第 5 关不看攻略能过；第 6 关失误后仍能重攒连击过关。

### P2 — 手感（约 1–2 天）

| 事件 | 档 | 反馈 |
|------|----|------|
| 翻牌/出槽 | 小 | 抬离桌面 + 轻 pop |
| 点中 | 小 | squash |
| 放对 | 小 | 落入盒、+分飘字 |
| 放错 | 中 | 闪红 + `wx.vibrateShort` + 弹回槽位 |
| 满盒消除 | 大 | 盒 squash、粒子、短暂停顿 |
| 连击 ≥5 | 大 | combo 音、字号弹出后收回 |
| 过关 | 大 | 星逐颗弹出 |

音效：短 SFX 进主包或分包。无长 BGM 则不必上传 `audio/`。提供音效开关和「减少动效」。可转发，不强制分享得奖励。

验收：闭眼能靠声音分清放对 / 放错 / 消除；切聊天再回来不黑屏。

### P3 — 提审包装（有独立 AppID 才能做）

- 类目「游戏 → 休闲 / 益智」、简介、竖屏截图 3–5 张、年龄提示
- 隐私协议游戏内 + 后台用户隐私保护指引
- **downloadFile 合法域名**：`https://oss.lliyuu520.cn`
- 体验版 → 提审。测试号不能发正式版
- 不复用怒雷的备案/AppID；新游戏单独备案（周期可能十几个工作日，不挡 P0–P2）

## 10. 和上一版计划的差异

- **引擎**：自研 Canvas 2D → Cocos Creator 3.8.x。怒雷「禁止第三方引擎」只约束试点，不约束本项目
- **画面**：贴纸 PNG → 锁死摄像机的 3D 桌上玩具
- **主包关门**：< 1MB → **< 4MB**（运行时本身就占一块；资源走分包/CDN）
- **CDN 对象**：`sortking/items/*.png` → `sortking/models/*.glb`（PNG 留作对照）
- **P0**：从「Platform 适配 + emoji」改为「Cocos 构建进微信 + 占位物拖拽」
- 增加 P0.5 模型管线
- 明确关掉 3D 物理
- 平台规则、备案、AppID、CDN 域名、儿童向、无广告：**与怒雷试点结论相同**
